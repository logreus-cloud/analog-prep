# Аналог — тот же препарат дешевле

Пациент вводит название с упаковки и получает зарегистрированные препараты
с тем же действующим веществом, ценой за месяц приёма и отметкой о праве на
бесплатное получение. А если замена опасна — не получает ничего, кроме
объяснения, почему её должен подбирать врач.

**Демо:** _вставить ссылку на развёрнутый стенд_
**Трек:** Здравоохранение · **Команда:** _двое, имена_

> Первая загрузка спящего стенда занимает около 30 секунд — бесплатный
> инстанс Render засыпает после 15 минут простоя. Дальше всё мгновенно.

---

## Проблема и ценность

Пациент с хроническим назначением покупает препарат по торговому наименованию
из рецепта. О том, что у того же действующего вещества есть зарегистрированные
аналоги дешевле в два-три раза, он чаще всего не знает: в рецепте написано одно
название, в аптеке предлагают его же.

Дальше происходит одно из двух. Либо человек платит вдвое больше, чем мог бы.
Либо, столкнувшись с ценой месячного курса, бросает лечение — и возвращается
в систему здравоохранения уже с обострением, которое обойдётся дороже всем.

Отдельная категория пациентов платит за препарат, который положен ей бесплатно
по амбулаторному лекарственному обеспечению, потому что об этом праве не знает.

**Для кого:** пациент с постоянным назначением — гипертония, диабет второго
типа, повышенный холестерин, гипотиреоз. Вторично — участковый врач, которому
на приёме важно понимать, потянет ли пациент выписанный курс.

**Ценность измеряется не экономией, а приверженностью терапии:** пациент,
который может позволить себе курс, его допивает.

### Почему это здравоохранение, а не сервис поиска по ценам

Три вещи отличают продукт от прайс-агрегатора, и все три заложены
в конструкцию, а не в описание.

**Система умеет отказывать.** Для препаратов узкого терапевтического диапазона
замена запрещена: разница в усвоении между производителями клинически значима.
На таком запросе не показывается ни одной цены и ни одной кнопки — только
объяснение и предложение обратиться к врачу.

**Правила отделены от модели.** Решение о допустимости замены принимает код,
а не языковая модель, и модель не может его отменить. Подробности ниже.

**Право на бесплатное получение важнее скидки.** Если препарат входит
в перечень льготного обеспечения, система говорит об этом до того, как
покажет, где он дешевле. Это работа с доступностью помощи, а не с розницей.

## Как это работает

```
ввод пациента
     │
     ├─► локальный поиск по справочнику (lib/search.js)
     │     совпадение по синонимам, допуск опечаток, разбор дозировки
     │
     ├─► если не узнал — один вызов модели (lib/llm.js)
     │     выбор строго из перечня справочника, иначе честное «не найдено»
     │
     ▼
правила безопасности (lib/safety.js)  ◄── работают ВСЕГДА, до и независимо от модели
     │
     ├─ запрет   → объяснение, список замен не собирается
     └─ разрешено → замены той же дозировки и формы, цена за месяц приёма
```

Порядок здесь принципиален. Модель стоит **после** локального поиска, а не
перед ним: девять запросов из десяти обслуживаются справочником — мгновенно,
без сети и без расхода квоты. Продукт остаётся работоспособным, даже когда
внешний API недоступен полностью.

## Быстрый старт

**API-ключ не нужен.** Демо-режим включён по умолчанию: вместо обращений
к модели проигрываются записанные ответы, а поиск по справочнику от модели
не зависит вовсе.

```bash
npm install
npm start          # http://localhost:3000
npm run smoke      # семь сценариев из спецификации
```

Проверить боевой стенд тем же файлом:

```bash
BASE_URL=https://ваш-сервис.onrender.com npm run smoke
BASE_URL=https://ваш-сервис.onrender.com npm run wake   # разбудить перед показом
```

Живая модель — только для разработки:

```bash
cp .env.example .env     # GEMINI_API_KEY=..., DEMO_MODE=0
```

## Основной сценарий

Четыре запроса показывают продукт целиком. Они же вынесены кнопками под полем
ввода — кликните, ничего печатать не нужно.

| Запрос | Что происходит |
|---|---|
| `Нольпаза 40` | Пантопразол, пять взаимозаменяемых препаратов, экономия около 2 900 ₸ в месяц |
| `Эутирокс 50` | **Замена запрещена.** Левотироксин — узкий терапевтический диапазон. Цен на экране нет |
| `Лизиноприл 10` | Замены плюс отметка: препарат положен бесплатно при подтверждённом диагнозе |
| `Глюкофаж Лонг 750` | Пролонгированная форма: обычный метформин в список не попадает, и об этом сказано |

Проверить границы продукта: `от головы что-нибудь` — система не подбирает
препарат по симптому и говорит об этом прямо.

## Технологии и структура

Express, ванильный фронтенд без сборки, справочник файлами в репозитории.
Внешних зависимостей одна — сам Express. Модель вызывается через REST,
без SDK, чтобы не зависеть от имени пакета.

```
server.js              три маршрута и /api/health с отметкой коммита
lib/catalog.js         загрузка справочника и индексы
lib/search.js          локальный поиск: синонимы, опечатки, дозировка
lib/safety.js          ЯДРО: правила допустимости замены
lib/pricing.js         пересчёт цены упаковки на месяц приёма
lib/llm.js             единственная точка обращения к модели
lib/fixtures.js        записанные ответы для демо-режима
data/substances.json   8 действующих веществ
data/products.json     35 торговых наименований
data/snapshot.json     дата и происхождение цен
public/index.html      один экран, три состояния
scripts/smoke.js       семь сценариев, локально и по боевому URL
```

## Границы и безопасность

Система **не назначает лечение, не отменяет назначения врача и не является
аптекой**. Она показывает справочную информацию о зарегистрированных
препаратах с одинаковым действующим веществом. Решение о замене принимает
врач или фармацевт.

### Правила, которые выполняет код, а не модель

| Код | Условие | Действие |
|---|---|---|
| `SR-01` | Узкий терапевтический диапазон: левотироксин, варфарин, дигоксин, литий, фенитоин, карбамазепин, циклоспорин, такролимус, теофиллин | **Запрет.** Список замен не собирается |
| `SR-02` | Рецептурный отпуск | Замены справочно, с пометкой о рецепте |
| `SR-03` | Другая лекарственная форма, включая пролонгированную | Исключение из списка |

Правила выполняются до обращения к модели. Модель не участвует в решении
и не может снять запрет: при срабатывании `SR-01` сервер возвращает **пустой
массив** замен, поэтому интерфейс физически не может их показать, даже
если кто-то забудет проверку в разметке.

**Что будет, если модель ошибётся.** В худшем случае пользователь увидит
лишнее предупреждение или «не найдено» вместо препарата. Ошибка в сторону
опасного совета конструктивно невозможна.

### О данных

Все цены — **вручную собранный снимок**, а не выгрузка из официального
источника и не остатки аптек. Дата снимка хранится в `data/snapshot.json`
и показывается на экране рядом с ценами.

> ⚠️ В текущей версии `snapshot.json` помечен как `ЧЕРНОВИК`: цены поставлены
> ориентировочные, при разработке. Перед демонстрацией заменить на собранные
> из открытых аптечных прайсов с указанием источника.

Персональные данные не собираются и не хранятся: на сервер уходит только
название препарата.

## Практическая применимость

Городская поликлиника и частная сеть клиник — как подсказка врачу в момент
выписки рецепта. Аптечные сети — как честный инструмент подбора у витрины.
Страховщик в системе обязательного медицинского страхования — как способ
снизить долю пациентов, бросающих терапию из-за цены.

Платит тот, кто выигрывает от непрерывности лечения: клиника, страховщик
или сама система здравоохранения, для которой обострение дороже курса.

## Потенциал развития

**Ближайшие месяцы.** Живые прайсы и остатки через интеграцию с аптечными
сетями вместо снимка. Казахский язык. Распознавание упаковки по фотографии.
Полный перечень льготного обеспечения вместо восьми позиций.

**Год.** Проверка лекарственных взаимодействий и дублирования действующего
вещества по списку препаратов пациента — самая частая проблема у пожилых
людей, принимающих пять-шесть наименований одновременно. Кабинет врача
с подсказкой в момент выписки рецепта.

**Дальше.** То же ядро — «свободный ввод пациента превращается в проверенную
структуру с правилами безопасности» — переиспользуется в разборе назначений
из выписки и в контроле приёма препаратов после стационара.

**Чего не хватает для реальной эксплуатации.** Справочник должен строиться
на государственном реестре лекарственных средств, а не собираться вручную.
Перечень препаратов узкого терапевтического диапазона и перечень льготного
обеспечения требуют проверки практикующими врачами и фармацевтами. До этого
продукт остаётся справочным инструментом, а не основанием для решений.
